# spike15d: whip -- classical control for spike15c "approach B" (same robust plan selection, uncertainty set from a classical estimator)

Section 0 was written 2 Nov 2026 ~18:20, BEFORE any spike15d method produced a number (nothing of spike15d had been run) and is not edited afterwards. Sections 1+ are appended after the runs. Statements marked **(inference)** are interpretation.
No locked set is touched: TEST 0-49, TEST-B 20000-20499, TEST-C 30000-30499 are blocked by a guard in the code (`experiments/spike15d/c15d.py`); `results/.test_access.log` must stay at 110 lines.

## 0. Pre-registration

**Question.** spike15c approach B (candidate pool c11, members = center + 3 frozen L-dec4 nets, worst-case aggregator "max", picked on CAL) lifted whip success from R0 69 % to ~87 % (= R1 true-theta). Fairness protocol K1 (classical and learned get the same tools): does the SAME robust selection rule, run on the uncertainty set of the CLASSICAL estimator (R0 = T-adapt3-full), get the same gain? If yes, the gain belongs to "robust plan selection", not to "learned estimator".

**Setting (identical to spike15c).** Whip, conditions abc x1, plant step /4, plant of each seed seed-derived. Pipeline = 0.6 s probe -> theta13 -> replay (chain state) -> planner (CMA-ES stage 1 -> 8 centre candidates, closed-loop rescoring) -> execution. R0 = T-adapt3-full (frozen cfg `results/spike10b/tune_full.json`), R1 = true theta. Everything below uses only the R0 probe data (the same 0.6 s open-loop probe); no true parameter, no learned network, no label enters the classical uncertainty sets or their selection.

**Seeds.** CAL = 1000-1049 + 2000-2149 (n=200; ALL selection). Holdout = 1100-1599 (n=500). New seeds = 704000-704199 (n=200, never used). Locked sets never touched (guard). Paired bootstrap, 20000 resamples, over episodes.

**Classical uncertainty sets (both built per episode from R0 probe data only; centre = the R0 estimate itself, bit-identical to the cached T-adapt3-full fit).**
* **MS (multi-start local solutions).** The R0 fit takes the 4 best of 343 grid starts through 3 prefix stages of bounded least squares. MS runs 12 starts with the same machinery: those 4 (this is R0, centre = best of them), grid starts ranked 5-8, and 4 random draws from the known generative parameter distribution (as spike14a C-map1-ms: ls U(.8,1.2); global log-mass U(-1,1) + per-link U(-.3,.3); log-damping U(-2,2); friction U(1,3) e-3). Every start is run to the final prefix (full probe), giving final cost and solution. Members = the 3 lowest-final-cost solutions that are DISTINCT from the centre and from each other (max-norm of (dx / x_scale) >= 0.1, x_scale = the fit's own (0.1 for length, 0.3 per link mass, 1 damping, 1 friction)). If fewer than 3 distinct solutions exist the missing members repeat the last chosen one (centre if none); the number of such episodes and the cost ratio (member cost / centre cost) are reported. No loss-tolerance gate is used for membership (it is only a reported diagnostic: fraction with cost <= 1.25 x best), so there is no extra tuning knob.
* **LAP (Gauss-Newton / Laplace posterior).** At the centre solution, J = Jacobian of the fit's own residual vector (probe residuals / (sq, sv) + the fit's regulariser terms) w.r.t. the 13 fit coordinates x (length, 10 log-masses, log-damping, friction). Posterior covariance Sigma = (J^T J + P)^-1, P = diag(1/sd^2) with the generative prior sd in x-space (length .1155, log-mass .60, log-damping 1.1547, friction .5774; the same quantities spike14a used for the classical MAP prior). No temperature scaling (scale 1). Members = draws x* + chol(Sigma) z, z~N(0,I) from an RNG seeded by the md5 of the probe key, clipped into the fit's bounds; the first 3 draws are M3, all 9 draws are M9. Residual bootstrap was NOT chosen (it needs refits; LAP gives a posterior from the same fit at no extra cost).
* Member counts aligned with B: M3c = centre + 3 members (primary); M9c = centre + 9 members (descriptive, LAP only; MS has no 9 distinct near-loss solutions by construction of 12 starts -> not run unless >= 9 distinct exist in the median episode, otherwise reported as "not done").

**Candidate pool and aggregator: identical to B.** Pool c8 (8 centre candidates from the centre-theta stage-1 CMA-ES + closed-loop rescoring) or c11 (c8 + each of the first 3 members' OWN best candidate: that member plans on its own theta and own replay-reconstructed chain state). Every candidate is scored in the closed-loop model of the centre and of every member (each with its own replayed chain state); aggregators mean / cmean / hit04 / hit06 / max over the chosen columns (code reused from `experiments/spike15c/analyzeB.py`: `choose`, `colset`). Every candidate is also EXECUTED on the true plant, so any rule is evaluated offline. Base candidate (argmin of centre score over c8) = the ordinary R0 episode (checked against the R0 reference run).

**Tuning budget (CAL only, <= 22 variants, B used 22).** Exactly 22 variants: family in {MS, LAP} x { pool in {c8, c11} x members M3c x aggregator in {mean, cmean, hit04, hit06, max} (10), + c11/centre/mean (1: R0 + extra candidates, no ensemble) } = 22. Selection = highest CAL success among the 22 EXCLUDING c11/centre/mean variants and the baseline (which are descriptive controls), i.e. among the 20 ensemble variants; ties -> listed order (MS before LAP; c8 before c11; mean, cmean, hit04, hit06, max). The winner is "C-ens". Selection is written to `results/spike15d/D_selection.json` BEFORE the holdout / new-seed collections are run. (Counting the 2 controls the family has 22 variants; the selection pool has 20, i.e. at most B's 22.)

**B (the learned side).** Fixed, NOT re-selected: c11 / M3c / max with the 3 frozen L-dec4 nets (`results/spike15c/models/model_r15dec4_s{0,1,2}.pt`). Holdout and CAL: spike15c stored per-episode results (`.scratch/s15c/B_{cal,hold}.pkl`, columns of members 0-2). New seeds 704000-704199: re-collected with the same code and frozen weights. L-ens (base candidate of B) and R0/R1 references are reported on all sets (R0, R1 re-run on 704000-704199; stored refs on CAL / holdout).

**Judgement rule (primary).** Difference d = B - C-ens (paired, per episode) on holdout (n=500) and on the new seeds (n=200), 20000-resample paired bootstrap.
* **"Learned estimator wins under robust selection":** on BOTH sets d >= +10 pp AND 95 % CI lower bound > 0.
* **"Classical control catches up" (TOST, margin +-10 pp):** on BOTH sets the 90 % CI of d lies inside [-10, +10] pp.
* Otherwise **"uncertain"**; additionally the +-5 pp description is reported (both 90 % CIs inside +-5 pp -> "within 5 pp"), and the point values.
Secondary: C-ens - R0 (paired, 95 % CI) and recovered fraction (X - R0)/(R1 - R0) with a bootstrap CI for X in {L-ens, B, C-ens, R0+c11/centre (selected family)}; the other variants, the other family, LAP M9c, and the member error statistics (RMS vs true theta of classical members vs L-dec4 members; for diagnosis only) are descriptive.

**Fairness notes written in advance.** (i) The classical side gets the same pool, aggregators, member count and tuning count as B. (ii) B's variant pick was made on CAL among 22; C-ens is picked the same way among 20; both picks are CAL winner's-curse exposed. (iii) The classical set construction (12 starts, eps = 0.1, prior sd, scale 1) is fixed here; a post-hoc sensitivity (e.g. Laplace x2 width) would be labelled descriptive and not enter the verdict. (iv) The classical uncertainty sets use the generative parameter distribution as a prior (as in spike14a, the classical counterpart of simulator labels); this is disclosed, not neutral. (v) Cost differs: the learned members are forward passes; the classical sets cost ~3x the R0 fit in cpu-s (reported).

**Budget reported (three axes) for both sides:** episodes (full-episode equivalents), wall-clock (cpu-s and wall), label source.

**Hard limits.** Total wall <= 6 h; heavy runs under `flock .scratch/heavy.lock` + `systemd-run MemoryMax=10G`, <= 8 workers, `free -h` available >= 8 GB before each start; GPU not needed (CPU inference of 3 small nets). Writes only in `experiments/spike15d/`, `results/spike15d/`, `.scratch/s15d/`. No commit; docs/ untouched.

# Results (appended after the runs)

## 1. Results (numbers: `D_table.md`, `D_summary.json`, `D_selection.json`; code `experiments/spike15d/`)
* Selection on CAL (before hold/new): C-ens = LAP/c11/M3c/hit06 (CAL 81.0 %; MS family best 74.5 %). B on CAL 91.5 %.
* Holdout n=500: R0 69.2, R1 86.0, L-ens 71.0, B 86.6, C-ens 79.6 (+10.4 vs R0 [+5.6,+15.0], recovered 0.62 [0.39,0.86]), R0+c11/centre: MS 70.0, LAP 73.6. B - C-ens +7.0 (95 % [+2.6,+11.4], 90 % [+3.4,+10.6]).
* New 704000-704199 n=200: R0 63.0, R1 81.0, L-ens 68.0, B 82.5, C-ens 78.5 (+15.5 vs R0 [+8.0,+23.0], recovered 0.86 [0.51,1.33]); B - C-ens +4.0 (95 % [-3.0,+11.0], 90 % [-2.0,+10.0]).
* Verdict (section-0 rule): **UNCERTAIN** (win needs >= +10 both: no; TOST +-10: holdout 90 % upper 10.6 > 10, no; within +-5: no). Direction: B ahead by 4-7 pp on both sets; the classical Laplace-posterior ensemble recovers most (0.6-0.9) of the R0->R1 gap, i.e. most of the gain is due to robust selection itself.
* MS (multi-start) family is degenerate: on holdout 439/500 episodes have no distinct local solution (members = centre), 31 have 3; MS ensemble gains ~0-1 pp. Descriptive M9 (LAP, 9 members): holdout 80-82 %, B - M9 +4.4..+6.8; new 80-84 %, B - M9 -1.5..+2.5.
* Member error (log-damping RMS, holdout): R0 centre 0.69, LAP draws 0.83, L-dec4 members 0.32 (ensemble 0.32). (inference) learned members are far more accurate yet the selection gain gap is only 4-7 pp.
* Control: base candidate reproduces the R0 episode outcome in 100 % of episodes (all sets, both families).
* Budget: new episodes collected: classical per family 900 (11 candidates each executed) + B-new 200; classical sets 40-46 cpu-s per episode (~3x R0 fit), total cls cpu ~40,300 s, wall ~5,250 s; collects wall LAP 1461 s / MS 415 s; labels: none (classical); B new 367 s. Total spike wall ~2.7 h.
* Deviations: none from section 0. The verdict line in D_table.md is mis-ordered (cosmetic). No sensitivity run (Laplace x2) was made. MS M9 not done (no 9 distinct solutions). `results/.test_access.log` = 110 lines.

# spike15c: whip "fair learning side" trial -- can any learned method eat part of the ~+23 pp oracle headroom?

Section 0 was written BEFORE any spike15c method produced a number (2 Nov 2026, ~15:20) and is not edited afterwards. Sections 1+ are appended after the runs. Statements marked **(inference)** are interpretation, not measurement.
Trial only: no locked set is touched (TEST 0-49, TEST-B 20000-20499, TEST-C 30000-30499 are blocked by a guard in the code; `results/.test_access.log` must stay at 110 lines).

## 0. Pre-registration

**Setting.** Whip, realistic conditions "abc" x1, plant step /4, plant of each seed seed-derived (as spike13b/14a/15a). Pipeline = 0.6 s probe -> theta13 estimate -> replay (reconstruct chain state) -> planner (CMA-ES stage 1 + closed-loop rescoring of 8 candidates) -> execution. R0 = T-adapt3-full, R1 = true theta, L-ens = mean theta of the 3 frozen L-dec4 networks (spike15a weights `.scratch/s14/model_r15dec4_s{0,1,2}.pt`).

**Why these two approaches (feasibility reasoning, written before results).**
* The ladder (spike13b/15a) says the headroom is parameter precision (R0 -> R1 = +17 pp), chain state +5 pp, probe cost +2-4 pp. spike14a showed theta error halves but success barely moves, and success is "chaotic" in theta_hat (post-hoc: R1 + noise of L-dec4 size = 65 %). So a method that *hedges against the remaining theta uncertainty at planning time* is the most direct lever, and it costs no new RL.
* **Approach B (decision-oriented, ensemble/posterior-robust plan selection).** The existing planner produces 8 candidate swings from the mean-theta CMA-ES and picks the one that is best in the model of ONE theta_hat. B keeps the candidates but re-scores each in the closed-loop model of EVERY ensemble member (each with its own replay-reconstructed chain state), and picks by a robust aggregate. Variants: aggregator {mean min-distance, hit-fraction with mean-distance tie-break, worst case}; ensemble size {3 frozen, 9 = 3 frozen + 6 new seeds trained with the identical recipe, weights saved}; candidate pool {mean-theta candidates only; + each member's best candidate}. No gradient/RL, so no "learned vs not" optimisation failure mode of PPO. Base for B = R0 (primary judgement) and also reported against L-ens (its own natural base).
* **Approach A (asymmetric-critic residual PPO on top of the L-ens plan).** Actor sees the arm history features of spike13a (no privileged info), critic additionally sees true theta13 (z-scored), the estimator's theta_hat and the simulator chain state (qpos/qvel of the 10 links) at that step. Base = L-ens pipeline. Settings from spike13a: "fixed" recipe (separate clips, probe masked), log-std0 -2.0 (and -1.5 if -2.0 fails the gate), lr 1e-4, cap 12 Nm, H=256, 3 M steps, 32 envs, 3 training seeds. Training scenarios: 300 fixed seeds 600000-600299 (never used for training the estimators, so L-ens predictions on them are out-of-sample like on evaluation seeds; spike13a's pool 500000-500299 is inside the L-dec4 training set, which would make the base look better in training than in evaluation).
* **Not chosen (C):** BC from R2/R4 trajectories -> PPO. spike11a/12a showed BC students from multimodal teachers reach 14-60 %; and pipelined plan-then-track is not a stationary policy. Dropped on feasibility, not tried.
* Costly arms not tried: end-to-end differentiable fine-tuning of the estimator through the planner (planner is CMA-ES + MuJoCo, not differentiable). The GN trajectory loss in L-dec4 is already the differentiable surrogate.

**Seeds / splits.** CAL = 1000-1049 + 2000-2149 (n=200; ALL selection of recipes, variants, checkpoints). Holdout = 1100-1599 (n=500). New seeds = 703000-703199 (n=200, never used before). Estimator training data (frozen + new members) = seeds >= 500000 (<=575999) only; PPO training scenarios = 600000-600299. All paired comparisons use the same seeds and the paired bootstrap over episodes (20000 resamples), 95 % CI.

**Judgement rule ("eats headroom").** For an approach X with base Y (B: Y = R0 primary, Y = L-ens also reported; A: Y = L-ens zero-residual): X eats headroom iff X - Y >= +5 pp on BOTH the holdout (n=500) and the new seeds (n=200), and BOTH 95 % CIs exclude 0 (lower bound > 0). Both approaches are judged only for the CAL-selected recipe (one per approach, chosen before any holdout/new number of any variant is looked at; the other variants are evaluated afterwards, descriptively). Also reported: difference to R0 and recovered fraction (X - R0)/(R1 - R0) with a paired-bootstrap CI.
Because L-ens alone is already ~+5 pp over R0 on the holdout (spike14a, post hoc) and +8 on TEST-C, a "B beats R0 by >=5 pp" result could be just the ensemble; therefore B is ALSO required to beat L-ens to be called "eating headroom beyond the learned estimator" (stated separately; the user's primary rule uses B's own base, which I fix as R0 for B but report both).

**Gate for A (before any real-condition PPO is trusted).** Same env as the real run (base = L-ens pipeline, asymmetric critic), plus a constant torque bias of 6 Nm x (+1,-1,+1) on the arm joints after the probe (the exact cancelling action is a constant, so the learnable space is known). Recipe: log-std0 -1.5, 3 M steps, 1 seed, checkpoint chosen on CAL. PASS = holdout (1100-1599, n=500) success exceeds the zero-residual initialisation by >= 10 pp with CI lower bound > 0. If it fails, ONE further recipe (log-std0 -2.0 or a second seed) is allowed and disclosed; if that also fails, A's real-condition result is labelled "gate failed, uninterpretable" and no confirmation runs are made.
"Learned" check as spike13a: the CAL-selected checkpoint must beat init by >= 5 pp on CAL, else flagged "not learned"; the residual norm is always reported.

**Budget (three axes) reported per approach:** episodes (training + CAL selection evaluation, full-episode equivalents), wall-clock (cpu-s and wall), label source (simulator-privileged theta labels for the estimator; privileged critic inputs for A; none for the plain re-scoring in B). Deviations are appended in section "Deviations".

**Hard limits:** total wall <= 10 h from start (start ~15:10, stop 01:10 at the latest); VRAM <= 10 GB; every heavy run under `flock .scratch/heavy.lock` + `systemd-run MemoryMax=10G`, <= 8 workers; trained weights saved under `.scratch/s15c/` and copied to `results/spike15c/models/` when small.

# Results (appended after the runs; numbers: `B_table.md`, `B_summary.json`, `B9_*`, `runs/`)

## 1. Summary
* **Approach B (ensemble-robust plan selection): EATS headroom under the section-0 rule.** Rule fixed before results: pool c11 (8 center candidates + each member's own best), members = center + 3 frozen L-dec4 nets, worst-case ("max") aggregator, chosen on CAL (22 variants, CAL 91.5 % vs L-ens 77.5 %). Holdout n=500: R0 69.2, L-ens 71.0, R1 (true theta) 86.0, **B 86.6**: B-R0 **+17.4 [+12.6, +22.4]**, B-L-ens +15.6 [+11.4, +20.0], recovered fraction of R0->R1 1.04 [0.82, 1.32]. New seeds 703000-703199 n=200: R0 69.5, L-ens 74.0, R1 88.0, **B 88.0**: B-R0 **+18.5 [+11.0, +26.0]**, B-L-ens +14.0 [+7.5, +20.5]. Both CIs exclude 0 and exceed +5 pp on both sets, against both R0 and L-ens.
* **Extension (post hoc, after seeing the 3-net holdout result; selected on CAL inside the enlarged family, `B9_*`)**: 9 nets (3 frozen + 6 new seeds, identical recipe) -> c11/M9/mean: holdout 89.4 (+20.2 [+15.2, +25.2] vs R0), new 90.5 (+21.0 [+13.0, +29.0]). Descriptive; it is not the pre-registered pick.
* **Approach A (asymmetric-critic residual PPO on L-ens): sanity gate FAILED, so no real-condition runs were made (pre-registered).** Gate (6 Nm bias after the probe, log-std0 -1.5, 3 M steps, CAL-selected checkpoint, holdout n=500, init 55.2 %): seed 0 62.4 % = +7.2 [+2.0, +12.4]; seed 1 (the one further attempt allowed) 56.4 % = +1.2 [-4.0, +6.4]. Both below the +10 pp bar. Both CAL-selected checkpoints beat init by >= 5 pp on CAL (52 -> 64 / 60) with residual 5.6-6.0 Nm of the 6 needed, so the PPO is mechanically learning; the CAL-to-holdout shrinkage and seed spread are the failure (selection noise; the same pattern as spike13a's gate). A's real-condition number is therefore not reported ("gate failed, uninterpretable"). Not tried: log-std0 -2.0, more gate seeds, C (BC->PPO).
* Headline reading **(inference)**: the part of the headroom that PPO could not reach is reachable with no learning at the control level, by changing HOW the plan is chosen: the single-model rescoring step of the planner (also with true theta, R1 only 86 %) is the weak link; scoring each candidate across several plausible plants and taking the consensus beats it. Random candidate-count effect is controlled: c11/center/mean (more candidates, no ensemble) gives only 76.2 % on holdout.

## 2. Controls and checks
* Per-candidate executed outcomes make the selection rules offline-evaluable; the ordinary L-ens episode is candidate `base`. Ceiling (oracle pick of the best executed candidate): 99-100 % on every set, so the candidate pool contains a successful swing for almost every episode; the gain is selection quality.
* Leak audit by an independent read-only sonnet reviewer: no use of true theta/chain state/outcomes in selection; members' task_info overwritten by theta; selection variant chosen on CAL only (`select` vs `report`). Not independently re-run: that forced-candidate executions reproduce the ordinary episode (only the base candidate is the ordinary episode; others use identical noise streams by seed construction).
* L-ens here uses CPU re-inference of the frozen nets: theta differs from spike14a's stored predictions by up to 0.005 and L-ens holdout is 71.0 (spike14a 74.0): chaos/replicate noise of 1-3 pp, so L-ens numbers differ slightly from earlier spikes; all B-vs-L-ens contrasts are paired on the same inference.
* Variant spread on holdout (B_table.md): every ensemble-scoring variant with the c11 pool is 85.8-88.6 %, every c8 variant 78-80 %; so the result does not hinge on the aggregator pick.

## 3. Budget (three axes)
* B: no new training. Estimators = 3 frozen L-dec4 (13,120 full-episode equivalents each family as in spike14a; labels: simulator theta13 + 1,600 oracle plans) [+ 6 extra nets for the extension, GPU ~6 min]. Inference cost is the real price: 4 stage-1 CMA-ES plans per episode (center + 3 members) and 11 candidates x 4 (or 10) closed-loop scorings; collect wall 482 s / 200 episodes, 1324 s / 500 on 8 workers incl. executing all 11 candidates. CAL tuning: 22 (42) selection variants on 200 episodes, no extra simulation (offline). Label source for selection: none beyond the nets.
* A: gate runs 2 x 3 M steps = 16.0 k training episodes + 3.2 k CAL evaluation episodes (+ 3 x ~560 eval episodes), wall 1061 s + 763 s; labels: privileged critic inputs (simulator theta, chain state) only in training.

## 4. Deviations
1. Pool/ensemble candidates, aggregator list and member subsets were written into the code after the B design but before any CAL number; the M9 extension was added AFTER seeing 3-net holdout/new results (labelled post hoc).
2. GPU training of the 6 extra nets waited >1 h in the a GPU job queue queue (blocked by other projects); I kept waiting rather than switching to CPU; it ran later. Approach A runs used CPU (env-bound, tiny nets; as spike13a).
3. A: the gate allowed one further attempt, taken as a second seed of the same recipe; A confirmation not run by rule. Tuning budget for A is tiny (2 gate runs), so the failure is weak evidence about asymmetric critics.
4. B has no "3 training seeds" notion; it uses the 3 frozen training seeds jointly (and 9 in the extension). No replicate-noise estimate over repeated plan sampling.
5. Wall clock was dominated by waiting for the shared lock (spike15b); elapsed ~3.2 h of 10 h.
6. No locked set touched: `results/.test_access.log` still 110 lines; guard15c blocks 0-49, 20000-20499, 30000-30499.

## 5. Credibility
High for the direction and size of B's gain on in-distribution simulation (CAL/holdout/new all agree, CIs exclude 0 by wide margin, leak audit clean, controls above). Medium: single plant family, simulation only, estimators in-distribution, n=200 new-seed CIs wide, M9 extension post hoc, selection of the "max" variant on CAL (22 variants). Not yet confirmed on a locked set: that would need a pre-registered v9 card (candidate: c11 / M3c / max, and separately M9) and TEST-C is already spent (use a new locked set).

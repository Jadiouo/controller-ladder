All numbers: `table.md` (generated by `experiments/spike11a/report11.py` from the json files here). Statements marked **(inference)** are interpretation. No TEST seed (0-49, 20000-20499) was touched; `results/.test_access.log` is unchanged. Nothing outside `experiments/spike11a/`, `results/spike11a/`, `.scratch/` was modified.

## 1. Verdict (rule fixed in the task: best student >= T-adapt3-full + 10 pp on CAL)

**Not met. Not worth a formal experiment with this recipe.** Best-looking students: 71 % on CAL1+CAL2 (n=100, picked as best of 7 iterations on CAL1, i.e. optimistic) vs T-adapt3-full 64 % (+7 pp, CI not computed because selection-biased). On 200 fresh unseen seeds (700000-700199, never used for training or selection) the same student gets 58.0 %, the last-iteration student 58.5 %, the plain-MLP canonical student 59.5 %, versus T-adapt3-full 60.0 % and T-nom 55.5 %; paired difference to T-adapt3-full -2.0 pp [-11.5, +8.0], -1.5 [-11.0, +8.0], -0.5 [-10.0, +9.5]. The +10 pp rule is excluded (upper CI 8-9.5 pp) for every student. T-oracle (same canonical teacher) is 92.5 % on the fresh set (+32.5 pp), so the 89 % headroom of spike10b is real but the students recover none of it. Note T-adapt3-full is optimistic on CAL1 (78 %, its tuning set) and low on CAL2 (50 %); only the pooled or fresh numbers are comparable.

## 2. Step 1: teacher queries (CAL1, n=50, abc x1, SUBF=4)

The T-oracle is open loop for the chain (plan once at k=0, computed-torque tracking of a spline), so its action at ANY state, including student-visited ones, is just the plan reference at time t plus the CTC feedback: relabelling is free. A genuine replan from an arbitrary true state (arm moving, chain swinging) was also implemented (`c11.Replanner`: spline with initial velocity v0, span S = min(1.6, T_rem - 0.6), CMA-ES + closed-loop re-scoring from the true full state). Cost per query: 2.9-3.1 s mean (p90 4.6-5.8 s) on the shared machine (load 12-50); success of the replanning teacher 94 % for fixed plan, replan every 50 steps, every 25 steps (cold or warm start): no gain from replanning, because the oracle plan is already optimal for the true plant. Replanning every 25 steps while t <= 1.0 s costs ~24 s per episode. Main runs therefore label with the fixed plan (= T-oracle policy); replan labels (every 25) were used in one variant only (`dagger_25`).

## 3. Student

* Observation: noisy arm q, qd at lags 0 and 5, 10, ..., 30 steps (window chosen on CAL1 among strides 2/5/10 with 6 lags: BC 18 / 30 / 28 %, stride 5 = 0.15 s per lag chosen), time k/500, previous torque, task target (x, z), first measured q. No chain state, no plant parameters (diagnostic variants below add the true plant on purpose).
* Output: a tracking reference (qr - q, qdr, qddr) per step, followed by the SAME computed-torque inner loop as the teacher (same gains, same noisy obs). Reason: the reference is smooth and noise-free to label, the high-gain CTC absorbs encoder noise; a torque-output MLP would have to reproduce the noise cancelling.
* Nets: MLP 2x256 tanh (numpy forward); one offline arena `Flow` (4x256, one Euler step, noise fixed per episode) on the final aggregated data.
* Methods: BC; DART (noisy torque, AR(1) sigma 5 Nm rho 0.9, one setting); DAgger (student acts, teacher relabels, aggregate, retrain from scratch); beta-mixed DAgger (teacher acts on 50 %/25 %/.. of 25-step blocks).

## 4. What actually limited the students (the finding that matters for v8)

1. **The teacher is multimodal.** Planning the same scenario 4 times with different CMA-ES streams gives arm references that differ by 0.96 rad RMS, as much as two different scenarios do (0.92). A regressor learns the mean of incompatible solutions. With this teacher: BC 30 %, DART 30 %, DAgger 22-50 % (and getting WORSE with more iterations), replan-label DAgger 20-34 %.
2. **Canonical teacher** (continuation: nominal-plant plans on a 6x7 target grid computed along a serpentine path with warm starts, then CMA-ES warm-started from the interpolated grid plan with sigma 0.2, 1 restart; `experiments/spike11a/step_grid.py`, `c11.canon_x0`): within-scenario spread 0.27 rad vs between 0.73 rad, teacher success 92 % (CAL1 and CAL2), planning 1.1 s. DAgger students then reach 56-70 % on CAL (fluctuating +-10 pp between iterations).
3. **Prior-residual output** (student outputs the correction to the nominal-plant canonical reference of the target, which is a known prior): BC 42 % (plain BC 14 %), first DAgger iteration 71 %, then 51-62 % in later iterations. Fresh-seed numbers above show all of it is ~59 % once selection luck is removed.
4. **DAgger does not converge to the teacher (inference).** Validation MSE of the labels rises from 0.03 to 0.4 (normalised) as on-policy data accumulates: in BC data the arm history contains the teacher's own trajectory (copy-cat leakage; BC looks good offline, 92 % rollout success on its own data distribution), on student-visited states it does not and the label has to be inferred from a history that carries little information about the plant.
5. **It is not only missing plant information (diagnostic, inference).** Feeding the TRUE plant vector (13 numbers, `priv`) into the student gives 64-66 % on CAL1 (canonical, n=50) versus 56-66 % without; standard teacher 42-54 % vs 44-50 %. So even a student that knows the plant stalls near 60-65 %; the closed-loop task needs reference precision (hit radius 8 cm after a whip) that a per-step MLP/Flow regressor did not reach at ~600k samples (a one-step Flow on the same data: 59 %, same as the MLP). Training-seed rollout success of DAgger students is 55-66 % too, so it is a fitting/fidelity limit and not a CAL generalisation issue.

## 5. Budget

* Teacher-labelled training episodes (seeds >= 500000, rep 0, independent plant draw per seed, abc x1): BC data 400 (collected once per history window, 3x, same seeds); DART +400; dagger_fixed 400+4x200 = 1200; dagger_fixed_priv 400+3x200 = 1000; dagger_25 400+3x100 = 700; canon_dagger 1200; canon_dagger_priv 1000; canon_dagger3 (prior) 1600; canon_dagger3_b0.5 1600 (aggregates reuse data, so rollouts are 400-1600 per run, ~11k simulated training episodes in total). Seed ranges: 500000-500399, 510000, 520000+, 540000+, 560000+, 580000+, 600000+.
* Labels: simulator-privileged T-oracle (true per-link masses, friction, damping, length, true chain state); labels are the reference triple; no student ever sees them at test time.
* Evaluation episodes: CAL1 1000-1049 and CAL2 1050-1099 (n=100 total, added as allowed), plus 1000 fresh seeds 700000-700199 x 5 methods. T-adapt3-full evaluated with the spike10b frozen config; T-oracle = this spike's teacher.
* Wall-clock: ~3 h of ~6 h (machine shared, load 12-50). CPU only, no GPU used.

## 6. Deviations and limits

* The task did not ask for the canonical teacher, the prior-residual output or the privileged-plant diagnostic; they were added after the multimodality finding (documented above). Hyper-parameters (window, DART sigma, MLP size, iteration) chosen on CAL1 only; CAL2 is fresh for the rule-selected students but was looked at for all iterations of the later runs.
* One training seed per student; iteration-to-iteration swings of 10-20 pp show the student variance is as large as the effect being tested. No ensembling, no hyper-parameter search beyond what is listed; a different student design (plan-parameter output, longer training, larger data) is NOT excluded, only this recipe.
* Teacher trajectories use the TRUE noise-free state for planning, but the CTC executes on noisy observations like T-oracle in spike10b. T-oracle here (94/82 % on CAL1/CAL2 with the standard planner) differs slightly from spike10b's (90 % on CAL1 via c10b) because the plan starts from the true q0 instead of the noisy first measurement.
* Plant integration SUBF=4 as in spike10b; unstable-episode and diverged fractions were 0.00 for every evaluated set.
* DART tried with one noise setting only (teacher success under that noise 57 %, too large for an open-loop plan); not tuned.
